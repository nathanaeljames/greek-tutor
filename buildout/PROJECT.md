# Greek Tutor PWA — Project Spec and Decisions Log

Port of Dr. Ted Hildebrandt's ParsonsTech Greek Tutor (Asymetrix ToolBook,
Win 3.1, distributed as DOSBox bundle) to an offline-first mobile PWA.
Primary user: one learner on an iPhone with unreliable rural internet.
Full licensing permission from the author. Secondary goal: portfolio piece.

## Source material facts (verified by direct extraction)

- Two ISOs; GreekTutor.iso is the target (~277 MB). Hebrew is out of scope for v1.
- 42 ToolBook .TBK "books": 28 chapters + INTRO (6), VOCAB (2), JOHN (3),
  REV_PAR (2), REV_VOC. Books share one engine; Learn / Drill / Exercise /
  Quick Review menu template throughout. Stray "Hebrew" object names inside
  Greek books confirm shared engine with the Hebrew tutor.
- 8,521 WAVs, ~222 MB, mono 11,025 Hz 8-bit PCM. The most valuable asset.
- Drill logic is OpenScript embedded in .TBK; readable in fragments.
  DECISION: reimplement, do not port. Recovered script is reference only.
- Images: standard DIBs embedded in .TBK (small 16-color tiles verified);
  larger art may be RLE-compressed. DECISION: rebuild visuals in CSS;
  originals are reference via DOSBox screenshots.
- Fonts: GREEKTH.TTF is the Greek-script font, GKTRANS.TTF is Latin
  transliteration. Both legacy ASCII-mapped (zero Unicode Greek glyphs).
  Base mapping recovered by glyph rendering:
  a=alpha b=beta c=xi d=delta e=epsilon f=phi g=gamma h=eta i=iota k=kappa
  l=lambda m=mu n=nu o=omicron p=pi q=theta r=rho s=sigma t=tau u=upsilon
  w=omega x=chi y=psi z=zeta (uppercase parallel). Diacritics ride on
  punctuation/digit codes; mapping table still to be completed.
  DECISION: convert all text to Unicode polytonic Greek; ship no legacy fonts.
- Interaction audit: instructions are "Click on ..." throughout sampled
  books; no drag-drop evidence. User concurs from memory (10 yrs ago).
  DECISION: click-to-select interactions; no drag-drop library.

## Platform decisions

- PWA, offline-first. No App Store, no sideloading (7-day free-cert expiry
  makes sideloading unusable for a remote non-technical user).
- Stack: Svelte + Vite + vite-plugin-pwa (adapter-static/SvelteKit optional).
  Chosen over React once drag-drop (dnd-kit's edge) was ruled out.
- No Django/backend at runtime. Python is build-time pipeline only.
- Audio: AAC .m4a, 32 kbps, mono, 11,025 Hz, loudnorm-normalized.
  ~88 MB projected full set (verified by sample transcode: 40% of WAV).
  Chosen over Opus for iOS safety; over WAV for download size on bad rural
  internet (storage was never the constraint).
- Service worker precaches app shell ONLY. Audio pack is fetched once on
  first run into Cache Storage with a progress bar (not precached).
- Learner progress in IndexedDB, keyed by activity id. Never in content files.

## Naming contract (audio)

- File: mirror ISO structure, lowercased, .m4a.
  GKTUTOR/CHAPT_1/A_ALPHA.WAV -> audio/chapt_1/a_alpha.m4a
- Audio ID: relative path, lowercased, "/" -> "_", extension dropped:
  "chapt_1_a_alpha". Path-based because basenames repeat across chapters.
- audio-manifest.json maps id -> { src, orig }. Generated by
  transcode_audio.py (user runs locally) and independently derivable from
  the ISO listing (Claude side) — the contract keeps both in sync.

## Data model (v1, drafted and approved)

Global, load-once:
- lexicon.json: lemmas { greek, translit, gloss, pos, audio } and
  forms { lemma, greek, translit, audio, parse{...} }. Greek stored
  redundantly on forms (inflection not mechanically derivable).
- audio-manifest.json (above).
- parse-schemes.json: person/number/tense/voice/mood/case/gender enums.

Per chapter (chapters/chapt-01.json ... plus vocab/john/rev-par/rev-voc):
- { id, number, title, references[], objectives[], vocab[lemmaIds],
    learn[], drill[], exercise[], quickReview[] }
- Activities: discriminated union on "type", shared { id, type, title,
  instructions }. Seven types, one Svelte component each:
  1. contentAudio  — click-to-hear items (Learn pages, Quick Review charts)
  2. select        — prompt + options + one correct (the workhorse)
  3. match         — click-to-pair Greek/English
  4. spell         — build word from letter tiles/keyboard, accent-aware
  5. translate     — vocab drill both directions (may collapse into 2/3
                     after verification — confirm before building)
  6. parse         — grade against forms[ref].parse; fields reference schemes
  7. audioPlayer   — sequenced paradigm playback, Play/Pause/Stop

## Division of labor

Claude: content pipeline (Python, run in Claude's environment against the
RAR), draft lexicon + chapter JSONs, all Svelte/PWA application code,
delivered as downloadable zips.
User: local transcode (transcode_audio.py), content verification against
DOSBox screenshots (user has Greek expertise — treat drafted JSONs as
untrusted until verified), local dev (npm install / npm run dev), iPhone
device testing (PWA install, storage persistence, audio), GitHub repo +
hosting, optional author outreach for clean word lists (off critical path).

## Hosting decision

PWA must be SERVED over HTTPS (service worker requirement) — a download
link cannot install a PWA. Options: path on user's existing HTTPS site, or
Netlify from GitHub (user has done many). GitHub repo doubles as portfolio.

## Phase plan

1. DONE-ish: analysis, data model, transcode script (transcode_audio.py).
2. Pilot: Claude drafts Chapter 1 JSON + lexicon slice + font/diacritic
   table; user verifies against original.
3. Walking skeleton: Svelte PWA shell + chapter nav + select + contentAudio
   wired to Chapter 1. EARLY iPhone test here (de-risks PWA storage).
4. Build-out: remaining five components; chapter-by-chapter content with
   user verification loop.
5. Polish: audio-pack download UX, IndexedDB progress, install instructions.
6. Deploy: GitHub -> Netlify (or user's site).
